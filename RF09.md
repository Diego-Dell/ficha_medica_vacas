# Administración del sistema

RF-09 usa la cuenta administradora existente de Supabase, sin asignarle un rol de dueño ni de veterinario. La aplicación conserva las pantallas compartidas de los demás módulos.

- Inicio: resumen real y hasta dos solicitudes pendientes.
- Granjas: búsqueda por nombre o RUNSA; pendientes abren revisión y confirmadas abren operaciones. Las rechazadas quedan fuera de la lista. Confirmar o rechazar regresa al listado.
- Cuentas: búsqueda por nombre o correo, edición de nombre, activación y desactivación, recuperación por correo y estado de cada acceso. Correo y privilegio administrativo no son editables. El administrador no puede desactivar su propia cuenta.
- Operaciones: ganado y antecedentes, datos de granja, clínica y reproducción, tratamientos, prevención, observaciones, aplicaciones y miembros. Se conserva la autoría original al corregir y Supabase registra al administrador que interviene.

La API compartida es `https://vetlink-api.onrender.com`. La rama de despliegue del backend es `supabase-render`; el desarrollo de RF-09 está también en `rf09-administracion`. El servicio personal de Render sirve para las pruebas de esa rama y no es necesario para ejecutar la versión integrada.

Para ejecutar la app se mantiene la configuración del equipo:

```sh
flutter run --dart-define-from-file=config.json
```

`config.json` debe contener la URL y clave **pública** del mismo Supabase y `API_URL` con la dirección compartida anterior. No se publica este archivo ni se utiliza una clave `service_role`. No hay servidor ni base en localhost.

Las cuatro migraciones `20261124*_rf09_*.sql` documentan los cambios de permisos y auditoría ya aplicados al Supabase compartido. La comprobación `supabase/tests/rf09.sql` se ejecuta en una transacción y termina con ROLLBACK; necesita una cuenta administradora y una trabajadora activas y una ficha activa en una granja confirmada.

La recuperación usa la clave pública configurada en Render o la que envía la app en el encabezado `apikey`, después de validar el token y el permiso administrativo. No cambia contraseñas desde el panel: envía el enlace del flujo existente.

Avisos y reportes son dependencias de RF-06 y RF-08. Sus accesos se mantienen deshabilitados hasta que el equipo integre esos módulos; no se muestran resultados ficticios ni se implementan versiones paralelas.
